# 第 4 课：领域 Schema 与确定性校验

上一课：[异步与错误处理](./03-error-handling.md) · [课程索引](./README.md) · 下一课：[结构化提取闭环](./05-structured-extraction.md)

## 目标与前置

建议 2～3 小时。需要完成第 3 课，并理解 Pydantic `BaseModel`、嵌套模型和列表。
当前已有模型与参考测试，不需要重新创建空工程。
本课不调用真实模型，目标是能区分“结构合法”“遵守提取约定”和“事实正确”。

## 为什么先定义契约

JSON 可解析不代表能用于业务。调用模型前先确定必填键、规则类别、未知值表示和拒绝条件。
完整字段表与合成示例只在[领域契约](../docs/schema.md)维护；先读该页，再回到下面的练习。

核心区别：

- 必填但可空：`airline_code: null` 表示键存在但信息未知，省略键则是结构错误。
- 空数组与未知数值：没有对应规则用 `[]`，未知件数用 `null`，明确零额度用 `0`。
- 说明字段：`note`、`special_notes` 无说明时用空字符串；其他受约束文本不能用纯空白代替未知。
- 类型与事实：两类行李解析为不同 Python 类型，但字段相同，Schema 本身不能发现模型放错了规则。
- 单位与文本：kg 表达是提取约定，Pydantic 不负责重量换算或事实核对。

## 动手任务

### 1. 追踪模型与输入

阅读[领域模型](../src/baggage_extractor/models.py)，画出
`ExtractionResult → BaggageRule → SizeLimit` 的对象关系，确认：

- 各对象使用 `extra="forbid"`，不删除未知字段后假装成功。
- 件数与尺寸使用严格非负整数，不自动转换字符串、布尔值或浮点数。
- 所有键必填，可空的值仍须显式提供。
- 模型不读取配置，也不依赖 Provider、Prompt 或网络。

不要因为 `checked_baggage` 名称像托运，就修改随身行李中的字段名；
这是当前外部契约，含义由所属数组决定。

### 2. 阅读测试并预测

阅读[模型测试](../tests/test_models.py)，预测合法完整结果、空数组、未知值、
负数、空白文本、缺键和额外字段的结果，再运行测试。
既有完整东航结果是结构测试数据，不代表当前航司政策或真实模型评估。

使用 `ValidationError.errors()` 检查出错字段路径和类型，而不是只捕获任意异常。
说明为什么 `"2"`、`2.0`、`True` 即使能被某些 Python 代码转换为整数，也不满足本契约。

### 3. 完成自己的变式练习

在自己的工作副本中扩展模型测试：

1. 给 `pieces` 传入 `True` 和 `1.0`，断言 `int_type` 错误；以 `0` 作成功对照。
2. 在完整结果的 `size_limit` 中增加 `unit` 键，断言 `extra_forbidden`，
   并核对嵌套路径中包含规则数组、索引与尺寸字段。
3. 将一个合法规则的 JSON 对象放入另一个规则数组，观察结构校验仍可能通过；
   在记录中解释为何还需要对照原文做质量评估，不据此修改 Schema 来伪造语义识别。

记录使用[学习模板](../../templates/learning-log.md)，保留命令、结果和解释。

### 4. 检查生成的 JSON Schema

使用 `ExtractionResult.model_json_schema()` 检查：

- 顶层四个键都必填，且拒绝未知字段。
- 两个规则数组引用对应的规则类型。
- `SizeLimit` 的四个键必填，三个尺寸是非负整数或 `null`。
- JSON Schema 能序列化，不包含未定义的版本、警告或其他业务字段。

不要手工复制一份 JSON Schema 到文档再维护；下一课直接从模型生成请求契约。

## 常见失败

- **未知字段被拒绝**：确认是否擅自扩展外部契约；不要全局改为忽略额外字段。
- **缺少尺寸键**：即使未知，也必须提供三个 `null` 值和字符串 `note`。
- **重量表达没有自动转成 kg**：这是 Prompt 的提取约定，不是模型类的字符串转换功能。
- **放错类别却未失败**：结构相同，事实边界必须由后续评估和领域逻辑验证。
