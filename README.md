# Path to AI Agent Engineer

面向已有软件开发经验的工程师，以 **AI 应用 / Agent 应用工程师**为默认目标，通过渐进式项目，学习构建**可测试、可评估、可恢复、可部署**的 AI Agent 系统。

不以训练基础大模型为目标，也不以掌握某个框架替代工程能力。先使用普通代码和确定性工作流，再判断是否需要 Agent。

## 从这里开始

1. 阅读[入门导航](./docs/start-here.md)，确认前置知识和学习方式。
2. 按[环境指南](./docs/setup.md)完成无 API Key 的离线验证。
3. 进入[第 1～4 课](./month-01-llm-foundations/lessons/README.md)，先完成练习，再对照参考实现。
4. 用[验收指南](./docs/assessment.md)判断是否掌握，而不是仅勾选“读过”。

**当前能运行什么？** 模型配置、异步文本调用、三组模型实验、计时、错误分类与有限重试、
行李额领域 Schema 和不访问真实模型的测试。

**当前还没有什么？** 结构化提取 API、RAG、Agent Loop、Docker 部署和模型质量评估器。
计划中的目录树、接口和指标不是已交付功能。

## 适合谁

- 会至少一种编程语言，了解 Git、HTTP 和基本自动化测试。
- 不需要机器学习背景；不熟悉 Python 的读者先完成[针对性补课](./docs/start-here.md#前置知识自检)。
- 想从“调用模型成功”进一步走向“可靠地接入真实业务”。

完成课程不等于已获得生产经验；作品集应诚实说明模拟环境、评估范围与已知限制。
共同基础之后，可选择[应用工程、Agent 平台或推理基础设施方向](./docs/career-tracks.md)，不把所有岗位的要求合并为必修清单。

## 三个渐进式项目

1. **航司行李额提取器**：可靠调用 → 小范围结构化输出 → 评估 → API 与基础部署。复杂行业规则为进阶，不强行包装成 Agent。
2. **研发知识与工具助手**：只读工具与 MCP 接入 → 上下文与知识问答 → 记忆隔离 → 受控工具服务与 Skills。
3. **可恢复的工单 Agent**：分类建议 → 人工审批 → 模拟业务操作 → 幂等与恢复 → 生产化。

目前只有[第一个项目](./month-01-llm-foundations)的起步实现。后两个项目尚未建立。
每个项目用[交付报告模板](./templates/project-report.md)说明业务收益、测试证据、失败接管与限制，而不只罗列技术栈。

## 运行原则

- **离线学习**：测试使用 Stub / HTTP Mock，不需要 API Key，不产生模型费用；首次安装依赖通常需要联网。
- **真实调用**：仅在学习者主动配置并执行时发生，会发送实验文本并可能计费，详见[配置与费用边界](./docs/setup.md#可选真实模型调用)。
- **质量与安全**：模型输出是不可信输入；单元测试通过不等于模型效果达标；敏感操作必须有权限边界和审批。
- **稳定技术主线**：当前使用 Python 3.13、HTTPX、Pydantic、pytest、Ruff；框架按后续模块需要引入。
- **AI 编程协作**：每个项目按[协作流程](./docs/coding-agent-workflow.md)完成一次小任务的委派、评审与验证；工具不可用时记录替代练习，不伪造使用经历。
