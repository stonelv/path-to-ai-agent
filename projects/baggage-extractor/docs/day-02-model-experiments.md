# Day 2 模型参数实验

> 作者的历史实验记录；跟做入口见[第 2 课](../lessons/02-model-calls.md)。
> 本实验同时改变了输入文本、Temperature 和输出上限，适合观察行为，不能把差异单独归因于某个参数。
> “完整性通过”“未发现臆造”是当次人工观察，不是固定评估集上的自动评分或供应商兼容性承诺。
> 当前文本实验已复用[版本化提取 Prompt](../src/baggage_extractor/prompts.py)，与下方历史提示词不同；
> 现在重跑相同命令不能直接复现这份记录。比较时需同时记录代码和 Prompt 版本。

## 实验信息

- 实验日期：2026-09-10
- 响应模型：`deepseek-flash`
- API 协议：OpenAI Chat Completions 兼容接口
- 数据来源：[国航托运行李规则](https://webresource.airchina.com.cn/zh-CN/content/travel_info/preparing/luggage/check/tyxlgz/)
- 来源访问日期：2026-09-10
- 运行命令：`.\.venv\Scripts\python.exe -m baggage_extractor.main`

实验文本根据国航页面链接的计重制和计件制免费托运行李额附件整理成连续语句，
用于学习和模型行为观察。

## 统一提示词

```text
你是航司行李政策分析助手。只根据用户提供的原文提取信息，不要补充原文未说明的内容。
分别列出每条适用规则，并保留旅客类型、舱位、航线、会员条件、件数及重量。
```

## 实验结果

### 实验 1：简单单规则

- Temperature：`0.0`
- 最大输出 Token：`1000`
- 延迟：`2.378` 秒
- 规则数量：1
- 完整性：通过
- 明显臆造：未发现

模型输出：

```text
1. 适用规则：
- 承运人：国航实际承运
- 航线：中国境内
- 航班类型：计重制航班
- 旅客类型：持成人或儿童客票的旅客
- 舱位：经济舱
- 会员条件：原文未说明
- 免费托运行李件数：原文未说明
- 免费托运行李重量：20公斤
```

观察：模型完整提取了承运人、航线、计重制、旅客类型、舱位和总重量，并明确标记原文
没有提供会员条件和件数。

### 实验 2：多舱位和多旅客规则

- Temperature：`0.3`
- 最大输出 Token：`1500`
- 延迟：`5.540` 秒
- 规则数量：6
- 完整性：通过
- 明显臆造：未发现

模型将成人或儿童客票的五种舱位拆成五条规则，并将婴儿客票规则单独拆出：

```text
1. 成人/儿童，头等舱，40公斤
2. 成人/儿童，公务舱，30公斤
3. 成人/儿童，悦享经济舱，20公斤
4. 成人/儿童，超级经济舱，20公斤
5. 成人/儿童，经济舱，20公斤
6. 婴儿，无论何种舱位，10公斤
```

观察：模型没有把不同舱位和旅客类型合并成一条，且正确指出原文没有说明件数和会员条件。

### 实验 3：复杂会员和舱位条件

- Temperature：`0.7`
- 最大输出 Token：`2500`
- 延迟：`7.070` 秒
- 规则数量：3
- 完整性：通过
- 明显臆造：未发现

模型输出摘要：

```text
1. 凤凰知音指定等级，头等舱或公务舱，额外1件，每件不超过32公斤
2. 凤凰知音指定等级，悦享经济舱、超级经济舱或经济舱，额外1件，每件不超过23公斤
3. 星空联盟金卡，无论何种舱位，额外1件，每件不超过23公斤
```

观察：模型正确保留了“额外免费托运”的语义，并按会员体系及舱位条件拆分为三条规则。

## 失败记录

首次尝试使用 `150`、`350` 和 `600` 作为最大输出 Token 时，三个请求均返回 HTTP 200，
但最终 `content` 为空。检查原始响应发现，该模型会在 `max_tokens` 额度内生成内部推理
Token；额度不足时可能没有剩余额度生成最终正文。

调整措施：

1. 将三档上限提高到 `1000`、`1500` 和 `2500`。
2. 在适配器中把空白 `content` 判定为明确错误，避免把 HTTP 200 误认为业务成功。
3. 为该行为增加 Mock 单元测试。

## 结论

1. 三组实验均正确覆盖了输入中的核心规则，复杂输入需要拆分成更多记录。
2. 本次单次实验中，输入复杂度、回答长度和延迟同时上升。
3. 较高 Temperature 的复杂实验未出现明显臆造，但单次运行不足以证明其稳定性。
4. `max_tokens` 对推理模型既可能限制内部推理，也可能限制最终回答，不能设置得过低。
5. HTTP 成功不等于业务成功；空正文仍必须由应用层拒绝。
6. 三组实验同时改变了文本复杂度、Temperature 和 Token 上限，因此不能据此单独判断某个
   参数对延迟或质量的因果影响。更严格的对比实验应固定输入，每个参数重复运行多次。
