# 航司行李额提取器交付报告

记录日期：2026-09-14

## 问题与范围

- 目标用户与原工作流程：面向需要把合成航司政策文本整理为结构化数据的学习场景；原流程是人工阅读并填写字段。
- 不使用模型的基线方案：由人工按领域契约录入；规则固定且来源结构化时应优先使用确定性解析，而不是模型。
- 为什么需要模型：政策文本表达不统一，模型用于候选字段提取；程序负责输入、JSON 和领域契约校验。
- 必做范围：中文合成文本、航司信息、免费托运与随身行李、舱位、重量、件数和尺寸；提供 CLI、固定评估与本地 HTTP API。
- 进阶范围：英文、会员叠加、单位换算、更大评估集和成本优化。
- 明确不支持：OCR、网页抓取、订座、收费、旅客权益判断、RAG 和 Agent Loop。
- 不允许自动执行的操作：不连接订座或收费系统；失败交由调用方或人工复核，不返回伪造的空结果。

## 实现与复现

- 代码版本：结构化输出兼容提交 `0680213`；FastAPI 服务提交 `e6d9bc9`；Docker 收尾以本报告所在提交为准。
- 模型与接口：真实基线使用配置名 `deepseek-flash`，DeepSeek Chat Completions，显式 `json_object` 模式。
- Prompt、Schema 与数据：`baggage-extraction-v2`、`baggage-result-v1`、`baggage-eval-v1`。
- 架构：FastAPI 是薄 HTTP 层，复用 `BaggageExtractor`、Provider、严格 JSON 解析和 Pydantic 领域校验。
- 关键取舍：供应商结构化输出能力由配置显式选择，不按错误自动降级；健康检查不调用模型；就绪只验证本地配置和对象创建。
- 本地安装与验证：

  ```powershell
  .\.venv\Scripts\python.exe -m pip install -e ".[dev]"
  .\.venv\Scripts\python.exe -m pytest
  .\.venv\Scripts\python.exe -m ruff check .
  .\.venv\Scripts\python.exe -m uvicorn baggage_extractor.api.app:app --host 127.0.0.1 --port 8000
  ```

- 容器入口：

  ```powershell
  docker build -t baggage-extractor:local .
  docker run --rm --env-file .env -p 127.0.0.1:8000:8000 baggage-extractor:local
  ```

- 外部边界：Stub 和 HTTP Mock 测试不访问模型；文本实验、提取 CLI、真实评估和 `POST /v1/extractions` 会发送输入并可能计费。
- 权限与数据：没有用户认证或租户隔离，只允许本地受控运行；密钥通过环境变量注入，日志不记录政策正文。

## 运行与限制

- 最小部署：本机 Uvicorn 已验证；Dockerfile 已实现非 root 用户、环境变量注入和健康检查。
- Docker 实机验证：当前机器没有 Docker 命令，镜像构建、容器启动及容器内就绪检查尚未执行。
- 故障发现：稳定错误代码、HTTP 状态、请求 ID 和脱敏日志。
- 人工接管：请求失败或字段事实不确定时由调用方复核原文；没有自动重试整个业务操作或写入外部系统。
- 回滚：回退应用版本和 Prompt 配置；没有数据库迁移或外部副作用。
- 已知限制：无认证、跨进程限流、费用熔断、P95、Token/成本采集、生产观测和公网加固。
- 下一项最有价值的改进：建立未查看的 holdout v2，再进入受控只读工具和最小 Agent Loop；Docker 实机验证可在有 Docker 的环境补做。
