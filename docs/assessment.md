## 学习者如何证明学会

每课提交给自己的证据包括：执行命令、实际结果、自己完成的变式练习，以及对失败原因和技术取舍的解释。
直接运行参考代码只能证明环境可用，不能替代独立练习。

| 当前课程 | 验收行为 | 证据 |
| --- | --- | --- |
| 01 工程初始化 | 独立完成安装，解释解释器、editable install、配置与测试的关系 | 包与配置测试通过；新增缺少配置的测试 |
| 02 模型调用 | 追踪消息到响应的路径，不依赖供应商对象 | HTTP Mock、契约、计时测试通过；新增可选请求 ID 的测试 |
| 03 错误处理 | 预测错误类型与调用次数，证明失败有边界 | 错误与退避测试通过；新增 403 不重试测试 |

具体任务、命令与提示在各课中。没有模型账户可完成以上离线验收，但真实调用和模型效果必须标记“未验证”。

## 三类验证不能混淆

| 层次 | 验证什么 | 运行边界 |
| --- | --- | --- |
| 程序正确性 | 序列化、配置、错误、重试；以后包括权限、状态和幂等 | pytest + Stub / Mock；无真实 API |
| 模型质量 | 提取是否正确，是否拆分规则、拒答或无依据补充 | 显式执行真实评估；当前评估器尚未实现 |
| 运行表现 | 延迟、Token、失败率、成本和服务恢复 | 记录环境与配置；当前仅实现基础计时 |

真实模型的回答与延迟会变化；一次成功、Temperature=0 或模型自报置信度均不能证明稳定质量。

## 后续结构化提取评估约定

在实现模块 02 时落地，不将下面的要求当作当前已有功能：

1. 每条样例具有 ID、输入、期望记录、来源/合成标记、适用类别和数据版本。
2. 分离开发集与固定留出集；同源或近重复政策不要分到不同集合造成泄漏。
3. 在评分前定义单位归一化、数值容差、缺失字段和多记录匹配规则。区分 `null` 与明确的零额度。
4. 分别报告字段匹配、多规则拆分、无依据字段补充和整条记录匹配；给出分母及失败样例，不只报一个总分。
5. 记录模型标识、Prompt、Schema、数据和代码版本、运行时间、样本数与调用失败数。失败不能从分母中静默删除。
6. 固定变量比较新旧版本，必要时重复运行报告波动。若使用模型评分器，记录其版本并人工抽查。
7. 先建立基线，再在比较候选版本前确定质量门槛；不事后改阈值来宣称通过。

第一月计划中的 100 条数据和质量百分比是初始教学目标，不是当前测量结果，也不是业务生产准入标准。
按计划扩充数据时分别说明开发集与留出集数量；数据量本身不保证覆盖充分。
费用以实际用量与对应价格记录，缺少用量时写“未采集”，不要填 0；延迟需注明是否包含重试。

## 课程发布门槛

- [ ] 标明已实现、未实现、前置条件和预计投入。
- [ ] 在声明支持的环境中按文档运行成功，记录未验证平台。
- [ ] 有动手任务、参考实现、预期行为和离线验收命令。
- [ ] 有至少一个失败案例及排错方法。
- [ ] 真实模型调用为显式选择，说明数据发送与费用边界。
- [ ] 链接和路径有效，测试不使用私人密钥。
- [ ] 示例数据的来源、隐私与再分发条件已核对。

维护者手工核对此清单，尚无自动课程发布平台。发现不满足条件时修复或降低状态，不用作者学习进度替代课程验收。
