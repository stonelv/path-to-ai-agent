## 学习者如何证明学会

每课提交给自己的证据包括：执行命令、实际结果、自己完成的变式练习，以及对失败原因和技术取舍的解释。
直接运行参考代码只能证明环境可用，不能替代独立练习。

| 当前课程 | 验收行为 | 证据 |
| --- | --- | --- |
| 01 工程初始化 | 独立完成安装，解释解释器、editable install、配置与测试的关系 | 包与配置测试通过；新增缺少配置的测试 |
| 02 模型调用 | 追踪消息到响应的路径，不依赖供应商对象 | HTTP Mock、契约、计时测试通过；新增可选请求 ID 的测试 |
| 03 错误处理 | 预测错误类型与调用次数，证明失败有边界 | 错误与退避测试通过；新增 403 不重试测试 |
| 04 领域 Schema | 区分结构校验、提取约定与事实判断 | 模型测试通过；新增布尔值、浮点件数和嵌套未知字段的拒绝测试 |
| 05 结构化提取 | 追踪 Schema 请求到结果，保留失败类型 | 提取器、协议和 CLI 测试通过；完成输入上界、嵌套失败和 CLI 变式 |
| 06 固定评估与评分 | 固定分母比较嵌套结果，区分遗漏、无依据补充和调用失败 | 加载、评分和报告测试通过；运行离线含错示例并完成四个变式 |

具体任务、命令与提示在各课中。没有模型账户可完成以上离线验收，但真实调用和模型效果必须标记“未验证”。

## 三类验证不能混淆

| 层次 | 验证什么 | 运行边界 |
| --- | --- | --- |
| 程序正确性 | 序列化、配置、错误、重试、JSON 解析与领域校验；以后包括权限、状态和幂等 | pytest + Stub / Mock；无真实 API |
| 模型质量 | 提取是否正确，是否拆分规则、遗漏或无依据补充 | 固定数据与确定性评分器；真实模型运行必须显式启用 |
| 运行表现 | 延迟、Token、失败率、成本和服务恢复 | 当前评估记录逐案例延迟和失败；Token、费用及重试次数尚未采集 |

真实模型的回答与延迟会变化；一次成功、Temperature=0 或模型自报置信度均不能证明稳定质量。

## 结构化提取评估约定

模块 02 已有固定合成数据、确定性评分器和显式真实运行入口；以下既是当前约定，也是扩展评估时的边界：

1. 每条样例具有 ID、输入、期望记录、来源/合成标记、适用类别和数据版本。
2. 分离开发集与固定留出集；同源或近重复政策不要分到不同集合造成泄漏。
3. 在评分前定义单位归一化、数值容差、缺失字段和多记录匹配规则。区分 `null` 与明确的零额度。
4. 分别报告字段匹配、多规则拆分、无依据字段补充和整条记录匹配；给出分母及失败样例，不只报一个总分。
5. 记录模型标识、Prompt、Schema、数据和代码版本、运行时间、样本数与调用失败数。失败不能从分母中静默删除。
6. 固定变量比较新旧版本，必要时重复运行报告波动。若使用模型评分器，记录其版本并人工抽查。
7. 先建立基线，再在比较候选版本前确定质量门槛；不事后改阈值来宣称通过。

第一月以关键正常、边界和失败场景覆盖为准，小型数据集可先建立闭环；100 条及复杂行业覆盖属于进阶参考，
不是唯一通关门槛。扩充数据时分别说明开发集与留出集数量；不预设脱离业务与基线的统一质量百分比。
费用以实际用量与对应价格记录，缺少用量时写“未采集”，不要填 0；延迟需注明是否包含重试。

## Agent 专项验收（规划）

从模块 03 的首个 Agent 项目开始落地，不代表当前已有 Agent 或评估框架。
每个任务定义初始环境、用户身份、允许操作、预算、预期终态及必要约束。
按模块逐步增加验收：例如持久恢复在模块 05 验证，不要求第一个只读 Agent 就实现所有平台能力；
尚未涉及的项说明不适用，已宣称支持但未执行的检查标记未验证。

| 对象 | 必测行为 | 验收证据 |
| --- | --- | --- |
| 业务终态 | 工单是否真正更新，知识答案是否有可访问的证据 | 查询模拟系统或结果存储，不只检查模型说“成功” |
| 工具轨迹 | 参数、授权、审批和工具选择符合约束 | 工具事件、必要的顺序/禁止操作断言 |
| 运行边界 | 步数、超时、预算和失败终止生效 | 终止原因、调用次数、费用/用量记录 |
| 重复试验 | 相同任务多次运行时结果是否稳定 | 固定任务的 trial 数、成功率及波动，不只展示最好一次 |
| 持久恢复 | 重启、超时、重复投递不造成重复副作用 | checkpoint 与业务数据核对，审批拒绝和恢复测试 |
| 上下文与记忆 | 压缩不丢关键限制，过期信息可纠正和删除 | 同任务预算对照、更新删除、跨用户/租户隔离测试 |
| 安全 | 恶意工具输出不能触发越权或泄漏 | 注入与拒绝授权案例；权限由程序实施，不只检查提示词 |
| 人工接管 | 无法完成或风险操作进入约定流程 | 接管原因、状态与恢复方式；接管不等于自动完成 |

轨迹评估检查必要约束，不强制所有有效方案使用完全相同的调用序列。
Trace 用来解释发生了什么，eval 用来判断是否达标；记录工具事件即可，不要求保存模型私有思维链。
日志和 Trace 需脱敏，限制访问及保留周期。

统计时区分成功、失败、取消、预算终止和人工接管，明确分母；终态正确但违反授权约束不能算通过。
重复试验使用重置或隔离的环境，不让前一次写入使后一次“虚假成功”。
比较框架、模型或 Agent 数量时保持任务与权限预算一致，记录随机性和环境差异。
可结合代码断言、人工评审与经过校准/抽查的模型评分，不把评分模型意见当作唯一事实。

### 评估与 CI 的边界

- 从早期课程复用已有测试运行器做离线回归；新增工具和状态能力时同步加入回归。
- 真实模型评估采用手动或受控定时触发，配置数据范围、预算、凭据权限和失败报告。
- 外部 PR 不自动获得密钥，也不自动运行付费评估；模型暂时不可用时标记未运行/失败，而不是悄悄跳过后宣称质量通过。
- Prompt、模型、Schema、工具和工作流变化后，按影响范围运行相应回归；至少一次跨模型或供应商的同集比较。

以上为后续门禁设计要求。当前仓库尚无自动 CI 或 Agent 评估器，不把规划当成已经执行的验证。
