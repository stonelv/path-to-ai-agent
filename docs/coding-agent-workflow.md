# AI 编程协作练习

[入门导航](./start-here.md) · [学习记录模板](../templates/learning-log.md)

本练习贯穿各项目，不要求特定品牌、订阅或云服务。使用组织允许的工具和可外发的合成数据；
未获授权时不要把公司代码、日志或凭据交给外部服务。
目标是学会委派和验证，而不是生成更多代码。开发复杂自主编程 harness 属于进阶选修。

## 每个项目完成一次小闭环

1. **定义任务**：选择一个边界明确的小变更，先写预期行为、允许修改的范围和验收方式。
2. **给出上下文**：提供必要接口、相关测试与限制，不倾倒整个仓库或用户数据。
3. **小步委派**：一次完成一个可检查的变更；真实 API、安装依赖、外部通信及写操作需单独确认边界。
4. **检查 diff**：确认未改无关文件、未泄漏凭据、未删除失败测试或用静默兜底伪造成功。
5. **独立验证**：执行已有针对性测试；涉及用户流程时补端到端验证，不把 Agent 自报“完成”当作证据。
6. **解释与复盘**：说明设计取舍、失败原因和修正过程。若未观察到错误就如实记录，不编造失败经历。

示例起点：完成[第 3 课](../month-01-llm-foundations/lessons/03-error-handling.md)时，
先自己预测 403 与 429 的调用次数，再让 Agent 补充 403 测试，审查它是否仅验证异常而漏掉“不重试”。
自己完成的理解与验收不能被工具替代。

## 需要留下的证据

- 任务描述与验收条件、提供了哪些必要上下文。
- 最终 diff 或提交标识，以及执行的命令和实际结果。
- 人工发现的问题、如何修正；未观察到错误时说明验证了哪些风险。
- 仍未验证的范围，以及不允许自动执行的操作。

在[学习记录](../templates/learning-log.md)和[交付报告](../templates/project-report.md)中归档脱敏摘要，
无需提交完整会话或包含原始数据的 Trace。

## 工具不可用时

可先手工完成任务，或与同伴进行“任务说明 → 实现 → 独立评审”的替代练习。
记录“AI 协作未实践”和后续补做项，不阻塞其他离线课程，也不将替代练习写成 Coding Agent 使用经验。
