## 项目演进

### A. 航司行李额提取器（00～02）

保留[当前项目](../month-01-llm-foundations)，逐步完成：

```text
文本调用 → 结构化输出 → 领域校验 → 固定评估 → API → 基础部署
```

不涉及真实订座、收费或自动抓取；原文没提供的信息不靠常识补全。
这是可靠 LLM 应用基础，无需为它强加 Agent Loop。

### B. 研发知识与工具助手（03、04、06）

只读研发工具与知识检索分别建立基线，再整合成助手，最后将工具以 MCP 提供。
知识数据默认使用可分发的合成资料；测试中明确区分用户权限。
代码审查助手可作为 Prompt / Precision-Recall 实验，不额外维护一个完整应用。

### C. 可恢复的工单 Agent（05、07）

在模拟业务系统中完成分类、补全、审批与状态更新。
用进程重启、重复请求、审批拒绝等案例证明恢复与幂等，而不只是展示成功路径。
真实外部写操作属于显式启用的进阶任务，默认不连接生产系统。

## 每个模块都要做的事

- **评估**：从少量有期望结果的案例开始，随能力增加而扩充；区分程序测试和模型质量。
- **安全**：配置与数据脱敏、输入验证、工具最小权限；后续加入审批和审计。
- **观测**：先记录模型、请求 ID、延迟与失败；后续扩充 Token、成本、Trace 和告警。
- **可靠性**：明确超时、失败和终止；有写操作后再验证幂等、补偿和恢复。

不把这些内容全部推迟到年度计划的第 9～11 月。

## 选修与节奏

- 先手写简单且有边界的 Agent Loop，再选择一个主框架重构，说明收益与代价。
- 多 Agent 为选修：在相同任务集上与普通工作流、单 Agent 比较成功率、成本和延迟。
- A2A、多模态和更复杂云架构按项目需要引入，不作为起步前置。
- 可以每周投入 10～15 小时，参考 20% 阅读、60% 实践、20% 测试复盘；以实际掌握为准。
- [原始年度计划](./annual-plan.md)保留原选题和时间安排，不要求每个月都新建项目。

每个毕业项目需包含问题定义、架构与取舍、运行方式、测试、评估报告、失败案例和已知限制。
公开演示前增加认证、限流、费用约束和数据审查，不把学习用服务裸露到公网。
