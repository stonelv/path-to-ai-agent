# 课程路线

[返回首页](../README.md) · [开始学习](../month-01-llm-foundations/lessons/README.md) · [验收指南](./assessment.md)

目标：从已有软件开发经验出发，学会设计、实现和验证可靠的 LLM / Agent 应用，而不是训练基础大模型或收集框架。
按能力依赖推进，已有经验者可提交等价验收证据跳过补课。模块编号与代码目录保持不变，目录中的月份不代表学习期限。
每周可参考投入 10～15 小时，按“理解原理 → 项目实践 → 测试复盘”循环，不按日期打卡。

## 关键模块的必修任务

### 模块 03：先做受控工具，再连接 MCP

- 用代码定义工具参数、输出、错误和权限契约；工具结果属于不可信数据。
- 实现有最大步骤数、超时、预算及终止原因的最小 Loop，与确定性工作流比较。
- 理解 MCP 的 host/client/server，使用 client 接入一个只读测试服务；不要求此时实现生产 Server。
- 从首个 Agent 开始保存小型任务集，验证工具参数、调用边界和最终结果。
- 加入恶意工具输出、拒绝授权和失败中止案例，不靠提示词代替权限校验。

### 模块 04：上下文、检索和记忆分别验收

1. **上下文工程**：固定任务，比较全量历史与按需加载；控制工具输出、Token 预算和压缩，检查关键约束是否丢失。
2. **RAG**：分开评估检索与回答，覆盖引用、拒答、权限过滤、更新和删除；需要时再引入混合检索与重排序。
3. **记忆**：区分本轮上下文、会话状态、业务执行状态和跨会话记忆；定义写入、来源、更新、失效、删除和租户隔离。

必做实验：同一任务在大量工具输出下比较成功率、延迟和成本；过期记忆应能纠正，用户 A 的记忆不得影响用户 B。
长期记忆不等于把聊天记录全部存进向量数据库，checkpoint 也不等于保证外部副作用只执行一次。

### 模块 06：分清 Tool、MCP 和 Skill

- Tool 执行具体操作；MCP 提供工具与上下文的互操作协议；Skill 组织任务知识、指令、脚本与资源。
- 为 MCP Server 增加身份、资源授权、输出限制和审计；凭据不直接交给模型生成的代码。
- 封装一个按需加载的 Skill，验证适用范围、资源加载和失败处理；安装第三方 Skill 前审查脚本与数据访问。
- 学习远程授权边界与协议安全实践，不使用 token passthrough，不把用户确认当作唯一安全机制。

### 模块 07：交付证据而不是功能清单

从早期模块逐步积累评估、Trace 和最小部署，在此统一验证灰度、回滚、告警和人工接管。
至少完成一次模型或供应商切换的同集回归；分别核对结构化输出、工具、流式事件与用量字段，
不假设兼容 API 就意味着能力一致。不自动发送私人数据或产生未经确认的费用。

## 三个渐进式项目

| 项目 | 模块 | 演进与能力证据 |
| --- | --- | --- |
| [航司行李额提取器](../month-01-llm-foundations) | 00～02 | 文本调用 → 结构化输出 → 固定评估 → API 与基础部署；证明能校验不可信输出、分析事实错误，不强加 Agent Loop |
| 研发知识与工具助手 | 03、04、06 | 只读工具 → MCP 接入 → 检索与上下文 → 记忆隔离 → 受控工具服务与 Skill；分别验证引用、授权和信息生命周期 |
| 可恢复的工单 Agent | 05、07 | 分类建议 → 人工审批 → 模拟业务操作 → 持久恢复；用重启、重复请求和审批拒绝证明幂等与接管 |

后两个项目尚未建立。不为每个技术点新建应用；代码审查可作为小实验，而不是第四个项目。
默认使用可分发的合成资料和模拟业务系统；真实外部写操作仅作为显式启用的进阶任务。
第一个项目的[范围](../month-01-llm-foundations/README.md#25-第一版范围)不包含订座、收费或抓取，
也不要求穷尽航司政策或凑满 100 条数据才能进入 Agent 学习。

## 每个模块都要做的事

- **评估**：从少量有期望结果的案例开始，随能力增加而扩充；区分程序测试和模型质量。
- **安全**：配置与数据脱敏、输入验证、工具最小权限；接入工具时加入提示词注入测试，有副作用前引入审批和审计。
- **观测**：先记录模型、请求 ID、延迟与失败；后续扩充 Token、成本、Trace 和告警。
- **可靠性**：明确超时、失败和终止；有写操作后再验证幂等、补偿和恢复。
- **AI 编程协作**：每个项目完成一次[小任务委派与验收](./assessment.md#项目交付与-ai-编程协作)，提交可解释的 diff、测试和失败复盘。
- **业务交付**：记录原流程、模型必要性、用户反馈或模拟评价、收益指标，以及不允许自动执行的边界。

这些内容随模块逐步增加，不全部推迟到最后的生产化阶段。
普通程序回归与真实模型评估采用不同的 CI 触发和预算边界，具体要求见[Agent 验收](./assessment.md#agent-专项验收规划)。

## 选修方向

默认完成应用工程主线，再结合已有经验选择一个深化方向，不把所有岗位要求合并为必修：

| 方向 | 适合延伸的经验 | 深化与作品证据 |
| --- | --- | --- |
| 应用工程（默认） | 后端、前端或全栈 | 业务接口、工具、RAG、效果迭代；展示任务成功与失败、收益或模拟评价。前端可补流式交互、取消与审批界面 |
| Agent 平台（选修） | 后端、平台或 SRE | 运行时、队列、多租户、预算治理；在已有项目上证明隔离、持久恢复、审计与回滚 |
| 推理基础设施（选修） | 云原生、容量与性能工程 | 模型服务、vLLM、GPU、编排与 SLO；提供可复现负载测试、资源成本和容量边界 |

GPU、付费平台不是共同起步条件；训练和算法岗位需另行学习数学、机器学习与训练体系。
求职时核实目标地区和经验级别的实际职责，不能把资深岗位要求当作入门门槛，也不把模拟实验写成生产经历。

- 先手写简单且有边界的 Agent Loop，再用一个主框架重构。后续教学参考优先选择 LangGraph 的状态与持久化能力，
  但这不是唯一就业技术栈；尚未添加框架依赖，具体版本在实现时验证。
- 多 Agent 为选修：在相同任务集上与普通工作流、单 Agent 比较成功率、成本和延迟。
- 应用轨可增加一个图像、文档或语音输入扩展；复杂 Coding Agent harness 属于开发工具或平台方向选修。
- A2A、微调、蒸馏和复杂自主规划按岗位或失败证据选修，不作为所有转型者的前置要求。

每个毕业项目使用[交付报告模板](../templates/project-report.md)，包含业务问题、非模型基线、架构与取舍、运行方式、
测试与评估、反馈、失败接管和已知限制。不把框架数量、Agent 数量或演示效果当作能力证明。
公开演示前增加认证、限流、费用约束和数据审查，不把学习用服务裸露到公网。

技术资料与招聘样本保留在[课程依据](./curriculum-sources.md)，仅供按需查阅；样本不是全市场统计或就业承诺。
